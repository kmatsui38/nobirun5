## 1. MVPのスコープ

### 目的

被験者（中2生徒2名）で「毎日コツコツ既習内容を復習することで学力が上がる」を定性検証するための最小プロダクト。

### 含むもの（企画書のMVP 4機能）

| # | 機能 | 概要 |
|---|---|---|
| F1 | 今日の復習 | 1日1セット（5〜10問）を自動生成して出題 |
| F2 | 即時採点・解説 | 解いたその場で正誤と解説を表示 |
| F3 | 苦手マップ | 単元×定着度をヒートマップ的に可視化 |
| F4 | ストリーク | 連続日数の表示・記録 |
| F5 | 自信申告 | 正解時に「明日も解ける自信ある?」を問い、次回出題間隔を補正 |

### 含まないもの（明示的スコープアウト）

- コーチ連携・順位・ピア機能（将来拡張）
- テスト前の「まとめて勉強」モード
- 定期テストの点数取り込み（システム外で確認）
- 課金・サブスク機能
- プッシュ通知（MVPでは家庭内の声かけで代替。将来的にはPWA化してプッシュ通知に対応したい）
- 数学以外の教科、中3の単元

### 対象コンテンツ

- **数学のみ**。単元は**中1(8単元)+中2(7単元)** = 15単元（[math-units.yaml](../../data/curriculum/math-units.yaml) の M1-*, M2-*）。
- 中2の2学期時点で既習の範囲に限定する（未習単元は出題対象から除外できること）。

### 解答形式の制約（重要な設計判断）

MVPは**自動採点可能な形式のみ**を扱う:

- **数値入力**（整数・分数・小数。例: `x = -3`、`3/4`）
- **選択式**（4択程度）

作図・証明・記述説明は出題対象外とする。証明単元（例: M2-B2 図形の合同）では、証明の穴埋め選択式など自動採点可能な形に変換して出題する。

## 2. ユーザーと利用環境

- **ユーザー**: 被験者の中学生2名。アカウントは運営者（親）が事前発行する。セルフサインアップは作らない。
- **デバイス**: スマホブラウザ最優先のレスポンシブWebアプリ。PCでも閲覧可能。
- **認証**: 事前発行のID+パスワード（簡易でよい）。セッションは長期維持し、毎回のログインを不要にする。
- **利用時間**: 1セッション5〜10分で完結すること。

### 主要フロー

```
S1 ログイン（初回のみ）
   ↓
S2 ホーム ──「はじめる」──▶ S3 復習セッション（5〜10問ループ）
   ▲                            │ 問題表示 → 解答 → 正誤+解説 → 次へ
   │                            ▼
   └──────────────── S4 セッション完了（ストリーク更新）
                                │
                                └──▶ S5 苦手マップ（任意で確認）
```

## 4. 学習ロジック仕様

### 4.1 定着度モデル

- 定着度は**学習事項レベル**（単元マスタの `knowledge_skills` / `thinking_skills` の各項目）で記録する。
- 各事項に **習熟ボックス(box) 0〜5** を持つ（ライトナー方式の簡易版）:

| box | 状態 | 次回出題までの間隔 |
|---|---|---|
| 0 | 未出題 | -（初回出題待ち） |
| 1 | 苦手 | 1日後 |
| 2 | 不安 | 2日後 |
| 3 | 定着中 | 4日後 |
| 4 | 定着 | 7日後 |
| 5 | 克服 | 14日後 |

- **正解**: box +1（上限5）。**不正解**: box を 1 にリセット（0には戻さない）。
- 単元の定着度 = 配下の事項の box の平均（苦手マップの色に使用）。

#### 自信申告（2026-08-27 追加）

**正解したときのみ**、解説の下で「明日も解ける自信ある？」を2択（自信あり / まだ不安）で聞く。

- **自信は定着判定の主決定因ではなく、出題間隔の補正因子**とする。box更新は上記の正誤ベースのまま変えない。
  - 中学生の自己評価は不正確になりがちで、「不安と答えると翌日また出る→面倒→自信ありを押す」というゲーミングも起こりうるため、主観をボックスの昇降に直結させない。
  - MVP検証の測定軸（定着度スコア）を守るためでもある。
- **「まだ不安」の場合のみ、次回出題間隔を1段短くする**（box n の間隔の代わりに box n−1 の間隔を使う。例: box3 なら 4日→2日）。boxは変えない。
- **不正解時は聞かない**（box=1確定で情報価値が低く、間違えた直後の追い打ち質問はUXが悪い）。
- **スキップ可能**。未申告は「自信あり」相当（＝現行挙動と同じ）として扱う。
- 申告値は解答履歴（attempts.confidence）に記録し、**「自信あり申告のうち次回も正解だった率」（キャリブレーション）を検証で分析**する。自信申告が信頼できると分かった段階で、定着定義への本格的な組み込みを再検討する。

### 4.2 「今日の復習」セットの生成

1日1セット、**7問**（最小5問・最大10問の範囲で調整可能な設定値とする）。次の優先順位で構成する:

1. **期日到来の復習問題**（box1〜5で次回出題日が今日以前のもの）— 苦手（boxが低い）順
2. **未出題事項の新規問題**（box0）— 既習範囲のうち後ろの単元（最近習ったもの）から優先
3. 枠が余る場合は box の低い事項から追加出題

制約:

- 同一テンプレートの問題は同一セット内に2問以上入れない
- 1セット内の単元数は3単元程度までとし、頭の切り替えコストを抑える

### 4.3 出題（テンプレート×変数方式）

- 問題は**検品済みテンプレート**から変数を差し替えて生成する（企画書v0.3の方式）。
- テンプレートは対象の学習事項ID（例: `M2-C1` の知識技能ア）に紐づく。
- 変数はテンプレート定義の**制約条件**（解が整数、負数を含む/含まない等）の範囲で乱択する。
- 同一ユーザーへの再出題時は変数を変えて出す（答えの丸暗記を防ぐ）。
- 解説もテンプレートで持ち、変数を差し込んで表示する（途中式含む）。

### 4.4 コールドスタート（初回利用）

- 診断テストは課さない（「1日5〜10分」の約束を守る）。
- 初回設定で**既習範囲**（学年と「どの単元まで習ったか」）を選択してもらう。
- 初週は既習範囲の直近単元から新規出題し、解答履歴で苦手を推定していく。

### 4.5 ストリーク

- その日のセットを**完了**（全問解答）した日をカウント。連続日数と自己ベストを記録。
- 途切れた場合はリセット。ただし表示は責めるトーンにしない（「また今日から」）。
- タイムゾーンはJST固定。日付の境界は午前4時とする（深夜学習の救済）。

## 5. データ設計（エンティティ概要）

```
users            ユーザー（id, nickname, grade, password_hash, created_at）
units            単元（math-units.yaml のミラー: id, grade, domain, name）
learning_items   学習事項（id, unit_id, kind: knowledge|thinking, text, seq）
templates        問題テンプレート（id, item_id, format: numeric|choice,
                 body_tmpl, var_constraints(JSON), answer_expr,
                 explanation_tmpl, difficulty, status: draft|ai_reviewed|approved）
user_scope       既習範囲（user_id, unit_id, learned: bool）
mastery          定着度（user_id, item_id, box: 0-5, due_date, last_result, updated_at）
daily_sets       今日の復習セット（id, user_id, date, completed_at）
set_questions    セット内の問題（set_id, seq, template_id, seed(変数の乱数種),
                 rendered_body, correct_answer）
attempts         解答（id, set_question_id, user_id, answer, is_correct, answered_at）
streaks          ストリーク（user_id, current, best, last_completed_date）
```

設計メモ:

- **units / learning_items は単元マスタYAMLから同期**する（マスタはリポジトリのYAMLが正）。
- 出題時に `template + seed` から問題を確定生成し、`rendered_body` と `correct_answer` をセットに保存する（後から「何が出題されたか」を完全に再現できるようにする。検証・不具合調査のため必須）。
- `templates.status` が `approved` のもののみ出題対象（正式ローンチ前チェック体制と接続）。
- 削除・退会フローはMVPでは作らない（被験者2名・手動運用）。

## 6. 非機能要件

- **スマホ最優先**: 縦持ち・片手操作で完結。数値入力は専用キーパッドUI。
- **速度**: 問題表示・採点はローカル即時（サーバ往復で待たせない設計を推奨）。
- **数式表示**: 分数・指数・√ を正しく表示できること（KaTeX等の数式レンダリング前提)。
- **運用**: 被験者2名のため可用性要件は緩い。ただし**解答履歴の消失は検証の失敗に直結する**ため、データのバックアップだけは確実に行う。
- **プライバシー**: 本名は保存しない（ニックネーム運用）。MVPは家庭内利用のため同意フローは省略(企画書の保留事項)。

## 7. MVP完了の定義（Definition of Done）

- 被験者2名が、スマホで毎日「今日の復習」を1セット完了できる
- 間違えた問題が間隔反復で再出題される
- 苦手マップで単元ごとの定着度が見える
- 運営者が2名の利用状況・解答履歴を確認できる（画面またはデータ出力）
- 中1・中2の既習範囲をカバーする approved テンプレートが揃っている（必要数はテンプレート設計フェーズで算定）
