# nobirun5（のびるん5）企画書

- 作成日: 2026-08-26
- 最終更新: 2026-08-27
- ステータス: 企画壁打ち反映済み（v0.3）

> **名前の由来**: 「5教科を伸ばす」こと。正式サービス名は未定で、当面は nobirun5 を仮称として進める。

## 1. サービスコンセプト

> **学力を伸ばしたいと思っている中学生が、日々コツコツとこれまで習ったことを復習していくことで苦手を克服し、最終的には学力がアップするサービス。**

キーワードは「**毎日コツコツ**」「**復習**」「**苦手克服**」。
新しいことを教える塾・授業アプリではなく、**既に習ったことを定着させる**ことに特化する。

## 2. 背景・課題

中学生の学力が伸び悩む典型的な原因:

1. **復習の習慣がない** — 授業で習っても、復習しないまま忘れてしまう（忘却曲線の問題）。
2. **何を復習すればいいか分からない** — 自分の苦手がどこにあるか本人が把握できていない。
3. **続かない** — 参考書や問題集は最初の数ページで挫折しがち。1回あたりの負荷が高すぎる。
4. **積み上げ科目でのつまずき** — 数学・英語は過去の単元のつまずきが現在の理解を妨げるが、遡って復習する仕組みがない。

## 3. 解決アプローチ

| 課題 | nobirun5のアプローチ |
|---|---|
| 復習の習慣がない | 1日5〜10分で終わる「今日の復習」を毎日自動で提示する |
| 何を復習すればいいか分からない | 解答履歴から苦手単元を自動で特定し、出題に反映する |
| 続かない | 連続記録（ストリーク）・成長の見える化で継続をゲーム的に支援する |
| 過去のつまずき | 間違えた問題の前提となる単元まで遡って出題する |

### コアとなる学習サイクル

```
毎日ログイン → 「今日の復習」(5〜10問) → 解答・即時解説 → 苦手を記録
     ↑                                                        ↓
     └──── 忘却曲線・苦手度に基づいて次回の出題を自動調整 ←────┘
```

- **間隔反復（スペースドリピティション）**: 正解した問題は間隔を空けて再出題、間違えた問題は短い間隔で再出題。
- **苦手マップ**: 教科×単元ごとの定着度を可視化し、「苦手が克服されていく」実感を与える。

## 4. ターゲットユーザーと事業戦略（2026-08-27 更新）

- **メイン**: 中学1〜3年生。「成績を上げたい」という意思はあるが、自分で学習計画を立てるのは苦手な層。
- **サブ**: 保護者（子どもの学習状況を見守りたい）。

### 事業戦略: 「eスピ！」との連携

nobirun5 は最終的に独立プロダクトではなく、**自社サービス「eスピ！」の追加コンテンツとして販売する**ことを目指す。

- **配布**: 一般向けの獲得チャネルは持たない。MVP検証はリファラル（身内）で行い、価値が証明された後に eスピ！受講生へ展開する。
- **差別化**: 学習機能単体では専門サービス（モノグサ、atama+ 等）に劣ることを前提とし、勝ち筋は eスピ！との共存に置く。
  - nobirun5 の成果を担任コーチが確認でき、褒めてもらえる
  - eスピ！受講者間で自分の現在地（順位）を把握できる ※順位の可視化は学力下位層の継続を損なうリスクがあるため実装時に要再検討
  - 同じ苦手を持つ受講生の勉強法を知れる

### ユーザー像（ペルソナ例）

> 中学2年生。部活で忙しく、机に向かうのは定期テスト前だけ。数学は1年生の「一次方程式」あたりから怪しく、テスト前の詰め込みでは点が伸びなくなってきた。スマホは毎日触る。

## 5. 主要機能（案）

### MVP（最初にリリースする最小構成）

1. **今日の復習** — 1日1セット（5〜10問）を自動生成して出題
2. **即時採点・解説** — 解いたその場で正誤と解説を表示
3. **苦手マップ** — 教科×単元の定着度をヒートマップ的に可視化
4. **ストリーク（連続記録）** — 継続日数の表示・記録
5. **対象教科** — まずは積み上げ効果が大きい **数学** 1教科から

### 将来的な拡張

- **eスピ！連携機能**（コーチ向け進捗画面、受講者間の現在地表示、苦手仲間の勉強法共有）— 本企画の勝ち筋だが、学習アプリ単体の価値証明が先のためMVPには含めない
- 英語・理科・社会・国語への教科拡大
- つまずきの前提単元まで遡る「さかのぼり出題」
- 定期テスト前の「まとめて勉強」モード
- 保護者向けの見守りレポート
- 定期テスト日程に合わせた出題範囲の調整
- AIによる解説のパーソナライズ・質問応答
- 継続支援の追加施策（ストリーク以外のゲーミフィケーション等）

## 6. 差別化ポイント

- **「教える」ではなく「定着させる」に特化** — 授業動画は持たず、復習体験の質で勝負する。
- **1日の負荷を意図的に小さくする** — 「物足りないくらい」で終わらせて翌日につなげる。
- **苦手克服のストーリーを見せる** — 点数ではなく「苦手だった単元が得意になった」変化を主役にする。

## 7. 成功指標（KPI案）

| 指標 | 意味 |
|---|---|
| 継続率（7日/30日） | 「毎日コツコツ」が実現できているか |
| 週あたり復習完了セット数 | 学習量の定着 |
| 苦手単元の克服数 | サービスの本質的価値 |
| 定着度スコアの推移 | 学力アップの代理指標 |

## 8. 想定する形態・技術方針（仮）

- **Webアプリ**（スマホブラウザ最優先のレスポンシブ設計。中学生の主デバイスはスマホ想定）
- 技術スタックは企画確定後に選定（候補: Next.js + データベース構成など）

## 9. コンテンツ方針（2026-08-27 更新）

- **問題コンテンツはAI生成する。** ただし、必ず**文部科学省の学習指導要領に準拠**して生成する。
- 学習指導要領を取り込み、教科×学年×単元の構造（単元マスタ）に整理したうえで、それを出題・生成の基盤とする（数学は作成済み → [docs/curriculum/01_数学単元マスタ.md](../curriculum/01_数学単元マスタ.md)）。
- **特定の教科書には準拠せず、学習指導要領のみに準拠する**（全教科書の共通基盤であり、著作権リスクも回避できるため）。

### 生成・品質担保の方式: テンプレート×変数のハイブリッド問題バンク

- AIがその場で自由生成するのではなく、**問題の型（テンプレート）を統一し、変数だけを動的に差し替える**方式を採る。これにより問題数は実質無限に増やせる。
- 品質チェックは**テンプレート単位**で行う: AIレビューで正当性を確認した上で、正式ローンチまでに人の目で全テンプレートをチェックする体制を作る。
- テンプレートごとに**変数の制約条件**（解が整数になる、途中式で負の数が出ない、難易度が単元想定を逸脱しない等）を定義する。
- 問題テンプレートを拡充する生成部隊は別リソースで稼働させる（リソースは今後確保する）。
- **初期コンテンツは中1・中2の単元を優先**する（MVP被験者が中2のため。中3・他教科は後続）。

## 10. 収益モデル（2026-08-27 更新）

- **MVP時点では無料**で提供する。
- 将来は**eスピ！のオプション（追加コンテンツ）として販売**する。課金形態はeスピ！の料金体系に準拠する。
- 課金導線を見据え、アカウント基盤は初期から設計に含める（実装はMVP後でよい）。

## 11. MVP検証計画（2026-08-27 追加）

- **被験者**: リファラルで確保した中学2年生2名（身内）から開始する。
- **検証する仮説**: 「毎日コツコツ既習内容を復習することで学力が上がる」こと。
- **検証方法**: n=2 のため統計的検証ではなく**定性検証**とする。定期テストの点数の変化・本人の実感・保護者の観察を測定点とする。
- **合格ライン（2026-08-27 確定・検証開始前に固定）**:
  - **成功**: 次回定期テストで数学の点数が前回比 **+10点以上**、または本人が「解ける問題が増えた」と実感し、保護者も変化を観察できた場合。
  - **撤退・見直し**: **4週間で利用が自然消滅**し、テストの点数にも変化がなかった場合。この場合は機能ではなく**コンセプト自体を疑う**。
- **副次的に観察する指標**: 「自信あり」と申告した問題が次回も正解だった率（キャリブレーション）。自己評価の精度が分かれば、自信申告を定着判定に本格的に組み込むかを判断できる。
- **スコープアウトするもの**:
  - 「続くか（継続率）」の検証 — 継続には学習以外の機能（eスピ！連携等）が重要であり、MVP機能だけでは測れないため。学力に課題感を持つ本人の意思に一定期待する。
  - コーチを巻き込んだ検証 — コーチ連携は「続けるため」の施策であり、まず学習アプリ単体で「学力が伸びるか」を検証する。
- **本企画は実験的な位置付け**であり、価値が証明されたらeスピ！展開の判断に進む。
